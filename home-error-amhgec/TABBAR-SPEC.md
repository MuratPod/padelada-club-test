# Таб-бар «стекло»: размеры v2 (замечания Мурата к TestFlight 101)

Автор: Padelada Design · 26.10.2026. Страница: экран «Таб-бар: размеры» в макете (состояния «Размеры» — аннотации поверх Главной со скроллом; «Лист» — значения, живые бары 320/360/390/430, таблицы запасов). Все числа — pt (CSS px в макете = pt).
Измерено на настоящем рендере: шрифт Golos Text 600 (woff2 из `@expo-google-fonts/golos-text`, тот же файл, что в приложении), реальная вёрстка `.tabs.glass`, 5 языков, ширины 320–430; границы глифов — по пикселям (4× растр). Скрипт: `tools/tabspec.py`.

## 1. Что нашёл при измерении (и чем решение отличается от первого предложения)

Предложенная геометрия «72 / внутренний отступ 8 / зазор 4 / 12 pt» **не решает** жалобу про «Профиль у края капсулы»: правый край слова на базовой линии (y = 61 из 72) лежит в зоне скругления радиуса 36, и расстояние от букв до контура капсулы получается **1,0 pt при ширине 360 и 3,5 pt при 390** (12 pt, ru). Причина — радиус 36 «съедает» нижний угол, а не нехватка места в ячейке. Что сделано:
- внутренний отступ 8 → **14** (подписи крайних ячеек уходят от дуги внутрь);
- зазор между ячейками 4 → **0** (ячейки не видны, а 16 pt зазоров отнимали у ячейки 4 pt; зазор между подписями при этом остаётся ≥ 15 pt);
- кегль **12 pt при ширине ≥ 375, иначе 11 pt** (правило из худшего слова «Профиль»: 53,6 pt при 12/600 не влезает в ячейку 61 с запасом 4 на сторону; при 11 — 49,1);
- высота 72 и вертикаль 6 · 44 · 14 · 8 остались: нижняя точка самой низкой буквы («р», «у») — y = 63,5, то есть **8,5 pt до нижнего края**, у букв без нижних выносных — 11 pt.

Критерий «запас до контура капсулы» принят ≥ 5 pt (≈ половина высоты заглавной), «до края ячейки» ≥ 4 pt, «между подписями» ≥ 8 pt.

## 2. Значения для React Native (pt)

```ts
// src/components/tabBarSurface.ts
export const TAB_BAR_HEIGHT = 72;
export const TAB_BAR_SIDE = 12;         // поле слева/справа от экрана; при ширине < 340 — 8
export const TAB_BAR_SIDE_SMALL = 8;
export const TAB_BAR_PAD_H = 14;        // внутренний горизонтальный отступ капсулы
export const TAB_PAD_TOP = 6;           // над линзой
export const TAB_LENS = 44;             // круг линзы; значок 22×22 по центру
export const TAB_LABEL_LINE = 14;       // строка подписи сразу под линзой, без зазора
export const TAB_PAD_BOTTOM = 8;        // 6 + 44 + 14 + 8 = 72
export const TAB_PADDY_W = 64, TAB_PADDY_H = 48;   // Paddy D1, по центру по вертикали (12 сверху и снизу)
export const TAB_MIN_BOTTOM = 12;
export const TAB_CONTENT_GAP = 16;

/** Низ капсулы от края экрана. iOS с индикатором «домой» (safe = 34): 20, индикатор виден в зазоре. Без индикатора (safe = 0): 12. */
export function tabBarBottom(safeBottom: number, os: 'ios' | 'android'): number {
  return os === 'ios' ? Math.max(TAB_MIN_BOTTOM, safeBottom - 14) : Math.max(TAB_MIN_BOTTOM, safeBottom);
}
export const tabBarSide = (w: number) => (w < 340 ? TAB_BAR_SIDE_SMALL : TAB_BAR_SIDE);
/** Ширина обычной ячейки: 4 одинаковых, Paddy 64 фиксированно, зазоров нет. */
export const tabCellWidth = (w: number) => (w - 2 * tabBarSide(w) - 2 * TAB_BAR_PAD_H - TAB_PADDY_W) / 4;
export const tabLabelSize = (w: number) => (w >= 375 ? 12 : 11);
/** Отступ снизу у прокручиваемого контента. */
export const tabBarContentInset = (safeBottom: number, os: 'ios' | 'android') => TAB_BAR_HEIGHT + tabBarBottom(safeBottom, os) + TAB_CONTENT_GAP;
```

Компонент:
- контейнер: `position:'absolute', left: side + insets.left, right: side + insets.right, bottom: tabBarBottom(insets.bottom, Platform.OS), height: 72, borderRadius: 999`, `paddingHorizontal: 14`, `flexDirection:'row'`, **без `gap`**. Если у `Glass` рамка 1 px — реальная граница в раскладке, тогда `paddingHorizontal: 13`;
- обычная ячейка: `width: tabCellWidth(W)` (или `flex:1`), `height: 72`, `paddingTop: 6`, `alignItems:'center'`; внутри линза `44×44` (значок `22`, по центру), под ней `Text` высотой 14. **Ячейка активной вкладки не расширяется** — линза 44 лежит по центру своей ячейки;
- Paddy D1: `width: 64, height: 48, alignSelf:'center'`, `flex: 0`;
- подпись: `fontFamily: 'GolosText_600SemiBold'` **для всех языков** (сейчас es/ca/en берут display-шрифт Montserrat Alternates 800 — он на ≈ 16 % шире: «Matches» при 11 pt 52,9 против 45,6), `fontSize: tabLabelSize(W)`, `lineHeight: 14`, `letterSpacing: 0`, `numberOfLines: 1`, `ellipsizeMode` не задавать (не обрезать), `textAlign:'center'`, `paddingHorizontal: 0`, на Android `includeFontPadding:false`;
- крупный шрифт ОС (`isLargeType`): прежний «столбик» не менялся; подписи в обычном режиме с `maxFontSizeMultiplier={1}`;
- прокрутка: `contentContainerStyle.paddingBottom = tabBarContentInset(insets.bottom, Platform.OS)` → iPhone с индикатором 72 + 20 + 16 = **108**, без индикатора 72 + 12 + 16 = **100**;
- прятание бара при скролле: `translateY` на `TAB_BAR_HEIGHT + bottom + 12`.

Android: на экранах с кнопочной навигацией `insets.bottom` = высота панели (≈ 48), поэтому там вычитать 14 нельзя — капсула наехала бы на кнопки. Вычитание 14 только для iOS (индикатор «домой» — тонкая полоска ~5 pt на 8 pt от края).

## 3. Расчёт ячейки (по формуле, поля 12; при ширине < 340 — 8)

ячейка = (W − 2·12 − 2·14 − 64) / 4 = (W − 116) / 4 → 360: 61 · 375: 64,75 · 390: 68,5 · 414: 74,5 · 430: 78,5. При W < 340 (поле 8): (W − 108) / 4 → 320: 53 · 340 (поле 12): 56.

## 5. Что менять относительно билда 101

Данные по билду 101 — по скриншоту и по вашим замерам (28 pt + safe-area ≈ 62 pt от низа); код TabBar.tsx в `src-festa` — более ранний снимок (высота 76, поля 16, отступ 6, подпись 11/13 Golos 700 для ru/uk и Montserrat Alternates 800 для es/ca/en), поэтому сверяйте с реальными константами билда.
1. **Низ:** 28 + safe (≈ 62) → `max(12, safe − 14)` на iOS (= 20 при safe 34): капсула ниже на ≈ 42 pt. Android: `max(12, safe)`.
2. **Высота:** 76 → 72 (внутри: 6 · 44 · 14 · 8).
3. **Поля:** 16 → 12 (при ширине < 340 — 8); **внутренний отступ:** 6 → 14, зазоров между ячейками нет.
4. **Ячейки:** вместо flex с расширением активной — равные ширины `(W − 116)/4`, Paddy 64×48 фиксированно.
5. **Подпись:** Golos Text 600 для всех языков, 12/14 (при W < 375 — 11/14), letterSpacing 0, одна строка без обрезки; подпись стоит сразу под линзой (без отдельного зазора 3 pt), нижний отступ 8.
6. **Низ контента:** paddingBottom = 72 + низ + 16 (108 на iPhone с индикатором).
7. Линза 44 и Paddy D1 — как утверждено, не менялись.

## 6. Проверки

- `check.py --lang all --widths 320,340,360,375,390,414,430 --taps` (700 видов): на 340–430 проблем нет; на 320 — только старая страница «Стекло и круг» (рамка-образец сужает бар до 288 → ячейки 43; это не реальный бар) и обрезка строки поиска «Falta uno · Looking for players» на Главной (EN, не таб-бар — вне этой правки).
- `contrast.py`: токены 0 провалов. `glass_contrast.py` (пиксели реального рендера, подписи и значки): реальные экраны 0 провалов (худший: тёмная тема, активная подпись 4,78); на синтетическом листе из плоских насыщенных блоков активная подпись в тёмной теме 3,51 на mint-блоке — справочно, в реальной ленте не воспроизводится.
- Тап-цели: ячейки 72 высота × ≥ 53 ширина (на 320), Paddy 64×48.
